# BuildRight EDS Data Source Status

**Last Updated:** December 16, 2025  
**Status:** ⚠️ Pending Architectural Decision

---

## Current Situation

`buildright-eds` currently uses locally cached data files that were generated by `buildright-aco`:

### Data Files in Use

| File | Location | Generated By |
|------|----------|--------------|
| `mock-products.json` | `data/mock-products.json` | buildright-aco (deprecated) |
| `project-recommendations.json` | `data/project-recommendations.json` | buildright-aco (deprecated) |
| `templates.json` | `data/templates.json` | buildright-aco (deprecated) |

---

## Problem Statement

**Issue:** Data files were previously generated by:
```bash
# In buildright-aco (now archived)
npm run generate:eds-data
```

This script:
1. Read ACO-format data from `buildright-aco/output/`
2. Transformed to EDS-compatible format
3. Wrote directly to `buildright-eds/data/` ← CROSS-REPO WRITE!

**Impact:**
- ✅ **No immediate breakage** (local copies exist and work)
- ⚠️ **Cannot refresh data** (buildright-aco is archived)
- ⚠️ **Data may become stale** over time

---

## Current Status

### ✅ **What Still Works**

- Frontend displays products correctly
- Project builder loads templates
- Material packages are accessible
- BOM generation works (via buildright-service)

**Reason:** Local data files are intact and functional

### ⚠️ **What Needs Fixing**

- Cannot regenerate `mock-products.json` from source
- Cannot update `project-recommendations.json` when templates change
- Cannot refresh `templates.json` when buildright-data changes
- No clear data refresh workflow

---

## Proposed Solutions

**See:** `/adobe-demo-system/BUILDRIGHT-EDS-DATA-TRANSFORMATION.md` for complete analysis

### **Option 1: Move to buildright-service** ⭐ RECOMMENDED

**Approach:**
- Create transformation action in buildright-service
- Expose as Adobe I/O Runtime endpoint
- Frontend fetches data via API

**Pros:**
- ✅ Proper separation of concerns
- ✅ Dynamic data transformation
- ✅ Reusable by other clients
- ✅ Aligns with service-oriented architecture

**Cons:**
- ⚠️ Requires API implementation
- ⚠️ Adds network dependency

---

### **Option 2: Add to commerce-demo-generator**

**Approach:**
- Generate EDS format alongside Commerce/ACO formats
- Output to `buildright-data/generated/eds/`
- Frontend reads from there

**Pros:**
- ✅ All generation in one place
- ✅ Consistent with generator pattern

**Cons:**
- ⚠️ Generator becomes less generic
- ⚠️ Static data (requires regeneration)

---

### **Option 3: Local Generation in buildright-eds**

**Approach:**
- Move transformation logic into buildright-eds
- Transform at build time or initialization

**Pros:**
- ✅ Frontend controls its own data format
- ✅ No cross-repo dependencies

**Cons:**
- ⚠️ Business logic in frontend
- ⚠️ Duplication if other frontends need same data

---

### **Option 4: Keep in buildright-data**

**Approach:**
- Create `buildright-data/scripts/generate-eds-format.js`
- Output to `buildright-data/generated/eds/`

**Pros:**
- ✅ All BuildRight data in one place

**Cons:**
- ⚠️ Data repo has transformation logic
- ⚠️ Blurs line between data and logic

## For Developers

### Current Data Format

**mock-products.json:**
```json
[
  {
    "sku": "STR-49C283DE",
    "name": "2x4x8 Pressure Treated Lumber",
    "price": 8.99,
    "category": "Structural Materials",
    "attributes": {
      "lumber_dimension": "2x4",
      "lumber_length": "8ft"
    }
  }
]
```

**project-recommendations.json:**
```json
{
  "templates": [...],
  "packages": [...],
  "personas": [...]
}
```

**templates.json:**
```json
[
  {
    "id": "sedona-2450",
    "name": "Sedona 2450",
    "sqft": 2450,
    "bedrooms": 3,
    "bathrooms": 2
  }
]
```

### Where Data is Used

**Frontend Components:**
- `blocks/product-grid/` - Uses mock-products.json
- `blocks/project-builder/` - Uses templates.json, project-recommendations.json
- `blocks/project-filter/` - Uses packages from project-recommendations.json
- `scripts/project-builder.js` - Main consumer of all data files

**Mock Service:**
- `scripts/aco-service.js` - Serves mock-products.json

## FAQs

### Q: Do I need to fix this immediately?
**A:** No. Current data files work fine. This is a technical debt item for proper data refresh workflow.

### Q: What if I need to update product data?
**A:** Currently, you would need to manually edit `data/mock-products.json`. This is acceptable short-term but not ideal long-term.

### Q: What if I need to add a new template?
**A:** Currently, you would need to manually edit `data/templates.json` and `data/project-recommendations.json`. This works but is error-prone.

### Q: Can I still use buildright-aco to generate data?
**A:** No, buildright-aco is archived. We need to implement one of the proposed solutions.

### Q: Which option should we choose?
**A:** Option 1 (move to buildright-service) is recommended. See `BUILDRIGHT-EDS-DATA-TRANSFORMATION.md` for detailed analysis.
